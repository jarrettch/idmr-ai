### P2: `search_within_document` still over-matches sibling titles

`src/lib/retrieval.ts` resolves loose document references before filtered search, but it still passes the resolved canonical title into `match_chunks_filtered`.

That RPC still filters with:

```sql
d.title ilike '%' || filter_title || '%'
```

So a within-document query for a title like `Satanic Spirits` can still retrieve chunks from sibling transcripts such as `Satanic Spirits in Ministers` or `Satanic Spirits to Demons`.

Fix B solved this for `search_by_title` by looking up the exact document and fetching by `document_id`. The filtered/vector path should use the same exact document-id constraint, or a new exact-title/document-id RPC.

Relevant files:

- `src/lib/retrieval.ts`
- `supabase/schema.sql`

### P2: Short catalog aliases are added but blocked by the resolver guard

The hardening work restores catalog aliases in `src/lib/document-aliases.ts`, but `resolveDocumentTitle()` returns `null` whenever the normalized user reference is under 5 characters.

That protects against generic short references, but it also blocks exact valid catalog aliases generated by the branch, including:

- `36B`
- `67US`
- `66CC`
- `66 H`

The resolver should special-case exact catalog-code aliases before applying the generic short-query guard, or otherwise distinguish known exact aliases from unknown short user text.

Relevant files:

- `src/lib/resolve-document.ts`
- `src/lib/document-aliases.ts`
- `scripts/build-aliases.ts`

### P3: `tsconfig.tsbuildinfo` is dirty in the branch worktree

`tsconfig.tsbuildinfo` is modified alongside the real pipeline hardening changes. This looks like local build/typecheck cache churn and should not be included in the branch commit unless the repo intentionally tracks it.
