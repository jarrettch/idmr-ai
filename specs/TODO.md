## Retrieval quality (found 2026-07-07)
Diagnosed from a real query ("Summarize the Sunday Morning in 74/75 transcript"): the model answered that only metadata/transcriber's notes were retrieved. Root cause is retrieval, NOT missing data — all 98 real transcripts are fully chunked (audited: 96 docs 21+ chunks, only the junk "Transcripts" index doc is thin). Two defects:
- **A. Proofreaders'-notes boilerplate embedded as content.** ✅ DONE (2026-07-07; hardening follow-up 2026-07-23). Added `scripts/strip-boilerplate.ts` — normalizes whitespace (the raw files hard-wrap mid-phrase), then removes the transcriber's/proofreader's convention sentences + scaffolding (underscore rules, "Page: Subject:" footers, catalog/cassette lines) by pattern, while PRESERVING contextual framing (DISPUTANTS, PRESENT ON TAPE, SPEAKER/READER, SUBJECT, location, "PLEASE NOTE" provenance). Wired into `scripts/chunk.ts`. The initial live run removed the then-known phrases, but a later artifact audit found additional convention variants; the 2026-07-23 hardening below closes those local gaps. The refreshed 9,783-chunk artifact still needs the planned live re-embed and smoke audit.
- **B. Brittle title resolution.** ✅ DONE (2026-07-08). Implemented entirely in application code (no schema change / no re-embed). `scripts/build-aliases.ts` extracts each transcript's content heading (date + spoken title + "also called" names) and disputants into `src/lib/document-aliases.ts` (committed, regenerable via `npm run aliases`). `src/lib/resolve-document.ts` resolves a loose reference to the canonical `documents.title` via trigram containment (per-field + union scoring, query-stopword stripping). `retrieval.ts` uses it: resolved refs fetch the exact document by id (precise); unresolved refs fall back to the old fuzzy ILIKE RPC. Regression test `npm run test:resolve` (17 cases). Verified live: "Sunday Morning in 74/75" → the vision transcript's full body, "the Christmas tape" → Carnal Mind Defined, "the debate with RN Hogan" → the debate. Off-topic queries correctly resolve to null (no forced match).

## Pipeline hardening (2026-07-09, from independent review of Fix A/B)
Review of the Fix A/B + multi-chat batch found three latent pipeline defects. Core branch-local defects fixed on `pipeline-hardening` (one RPC follow-up remains — see "Open" below); validated constraints noted so future changes don't regress them.
- **Stale-chunk cleanup in `embed.ts`.** The chunks upsert on `(document_id, chunk_index, page)` never deleted old tail rows when a document's chunk count shrank (exactly what stripper changes cause) — retrieval would serve stale duplicated text. Now after upserting, deletes `chunk_index > max` per (document, page) group (textbook restarts indexes per page). **Order matters: this must be live before any re-embed that shrinks documents.**
- **Resolver guards in `resolve-document.ts`.** Trigram containment is asymmetric by design (short ref vs long alias), so a reference that filler-strips to one generic word ("the tape" → "tape", "the 1971 lecture" → "1971") scored 1.0 against any alias containing it, and ambiguous refs (two docs have "Sunday Morning" aliases) silently tie-broke by alphabetical index order. Added: MIN_QUERY_CHARS=5 after filler stripping; AMBIGUITY_MARGIN=0.15 (winner must clearly beat runner-up) with a tightness tie-break (near-ties resolve only if one candidate's alias is covered far more by the query — keeps "carnal mind" → Carnal Mind Defined over the long Mystery-of-Iniquity title). Ambiguous → null → vector/ILIKE fallback. `test:resolve` now 23 cases.
- **Stripper region-anchoring in `strip-boilerplate.ts`.** The "exact wording can't swallow content" claim was false: `[\w.]+` accepted any word as a catalog value ("a catalog of the sins" lost "catalog of the" — the /i flag swallowing " the" via `[A-Z]{1,4}` was only the tail of it), and the cassette patterns mangled mid-body markers like "(END OF THE ORIGINAL 1ST 120 MINUTE AUDIO CASSETTE SIDE 2)" in 3 files. Content-eating patterns now match against the full normalized document and remove only complete spans ending within the validated 2,500-character preamble region, so an artificial slice boundary cannot terminate a regex and over-strip body text. Scaffolding (underscore rules, "Page: Subject:" — up to 242×/14× per file in the body) stays global. `preview-strip.ts` reuses the exported grammar, scans the full cleaned body, fails on convention survivors, and reports intentional mid-body catalog/cassette shapes for review. A 34-check adversarial/preservation suite covers all confirmed misses.
- **Catalog aliases restored and hardened in `build-aliases.ts`.** A shared parser now supplies both stripping and alias generation, with digit-led values, trailing-header protection (`DATE:`), en-dash separators, hard-wrapped-header handling, uncertainty `?`, and extraction of every catalog credit. The reviewed OCR value `67.O7l7 P` emits canonical `67.0717 P` plus the raw fallback. `aliases:check` detects generated-file drift. Junk "Transcripts" remains excluded from the alias index.
- Current local artifact: 9,781 chunks after the 2026-07-23 stripper/alias hardening and source-level exclusion of the 2-chunk junk "Transcripts" index (down from the prior 9,785). The shared exclusion policy is enforced by chunking, embedding, and alias generation. Requires live re-embed and spot checks before merge.
- **Audit follow-ups (2026-07-10 through 2026-07-23, `TODO-AUDIT-7-10.md` and `REVIEW-FIXES-7-15.md`).** Exact-alias fast path in the resolver (short catalog codes "66CC"/"36B"/"66 H" were unreachable under the min-length guard; unique verbatim alias equality now resolves at any length). Catalog extraction + stripper tolerate the transcriber's uncertainty "?" ("CATALOG #: 65? SSB" no longer yields a bare "65" alias / "? SSB" cruft — same for "70.11? SSD"). Resolver regression coverage now has 44 exact-title cases, including secondary, en-dash, hard-wrap, and reviewed-OCR catalog aliases.
- **Open (needs RPC deploy):** `searchWithinDocument` resolves the reference but `match_chunks_filtered` still filters `d.title ILIKE '%…%'`, so "Satanic Spirits" also pulls chunks from "Satanic Spirits in Ministers"/"… to Demons". Fix: document-id (or exact-title) mode in the RPC when resolved, keep ILIKE for unresolved refs. Ride along with the next live-Supabase session.
